# v0.1.1 — 시작 시 Output write failed 수정

사용자 실행에서 영상 정보 조회는 성공했지만 첫 `input-info.txt` 저장에 실패했다. 확인된 실패 경로는 261자였고, 같은 폴더의 `probe.log`는 256자, `error.json`은 257자였다. 원본 파일명을 로그 디렉터리 이름에 다시 붙인 설계와 Windows의 기존 경로 길이 제한을 처리하지 않은 파일 쓰기 코드가 원인이었다.

이전 시험은 원본 파일을 입력으로 사용했으나 출력 이름을 짧게 지정해 기본 저장 경로의 결함을 놓쳤다.

수정:

- 실행 로그 폴더를 출력 이름과 무관한 `rtxhdr-run-프로세스ID-시간값`으로 생성한다.
- 자체 파일 쓰기·프로세스 로그·최종 파일 이동에 Windows extended-length Unicode 경로를 사용한다. 시스템 설정을 변경하지 않는다.
- `CREATE_NEW`를 사용해 기존 파일을 원자적으로 보호한다.
- 파일 오류에는 실패 경로와 실제 Win32 오류 코드를 기록한다.

검증:

- 261자·340자 길이의 한글/공백 경로에서 정확한 데이터 저장·읽기 성공.
- 기존 파일 덮어쓰기 거부와 실패 메시지의 경로·오류 코드 확인.
- 같은 원본 전체 파일을 입력으로 3프레임 변환하고 긴 출력 이름으로 저장 성공: `artifacts/path-bug/rtxhdr-run-72500-286615968/result.json`.
- 원본과 같은 긴 파일명을 가진 발췌본을 입력하고 `--output` 없이 기본 저장 경로로 3프레임 변환 성공: `artifacts/default-path-bug/rtxhdr-run-56404-286650937/result.json`.
- 양쪽 실행에서 프로그램 내부의 HEVC Main10·HDR 색 태그·프레임 수 재디코드 검사를 통과했다. 이번 수정 검증은 시작 실패와 경로 처리를 대상으로 했으며 전체 23분 변환 완료를 의미하지 않는다.

회귀 시험: 빌드 후 `build/Release/FilePathTests.exe` 또는 CTest의 `file_paths`.
